# TideLine Google Analytics reporting

The only allowed Google owner is `q.stewart@tidelinestrats.com`. Collection uses property **560552440**, account **413284100**, stream **16194574972**, measurement **G-LCY7Q7N774**. Those resources were created with the visible Analytics account menu verified before and after creation. Always include the business email in `authuser` on dashboard links. Never restore the earlier wrong-account resources.

Reporting uses a dedicated internal OAuth app in Google Cloud project `tideline-analytics-2026`. Organization policy blocks service-account keys; leave that policy intact. No service-account credential is used. No paid Cloud services or billing activation is required.

Editors start a read-only OAuth connection from Company → Website. The endpoint also requires the active actor's email to match the TideLine owner. The callback uses PKCE, a separate short-lived HttpOnly cookie, one-use state, verified Google ID token and matching nonce/audience/email. It refuses other accounts even if the browser defaults to one. It does not change the Voyage login session. Refresh tokens are AES-GCM encrypted in the existing private database; the encryption key and OAuth client secret live only in Worker secrets. Tokens and credentials must never enter logs, public assets, chat context or browser storage.

The reporting adapter uses a fixed property, 15-minute cache and four bounded reports: daily sessions/views, period sessions/unique active users/views, acquisition channels, and `generate_lead` / `sign_up` event counts. GA4's America/Chicago reporting dates stay separate from the existing first-party UTC chart. Unique users are taken from Google's period report, never added across days. Empty new-property reports are pending collection, not invented zeroes. API failures retain cached records with original freshness and a stale label. Google thresholding, sampling and other-row data-loss flags remain visible. Browser conversion events are not a replacement for durable CRM records.

Deployment is coordinator-only. Provide a private `GA4_SECRETS_FILE` containing `GA4_CLIENT_ID`, `GA4_CLIENT_SECRET` and a base64url 32-byte `GA4_TOKEN_ENCRYPTION_KEY`. `wrangler deploy --secrets-file` publishes credentials and code together. Existing bindings and secrets are preserved. Reconcile the active provider version after any ambiguous deployment. Verify the actual signed-in Website panel, successful authorized reporting and exact release revision before completion.
