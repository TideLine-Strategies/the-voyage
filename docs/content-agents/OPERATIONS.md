# Content Factory operations

The source of authority is the seven versioned policies in this directory. Run
`node scripts/content-agent-docs-build.mjs` after an intentional policy edit;
tests verify exact runtime text and SHA-256. Living observations reside privately
in `content_agent_docs`, linked to durable completed/failed runs. They never
replace policy gates.

The existing signed operator refreshes three curated public creator RSS feeds at
most every six hours, checks queued decisions every five minutes, and queues one
analytics review per UTC day. LLM decisions use the existing Codex login, a bounded
input/schema, no tools, a 90-second timeout and a claim lease. Seven workflow
steps can request judgment. Scripting returns explicitly unapproved draft copy
and proposed shots; approval and posting runs return recommendations only.

Feed metadata supports dated topics and observed counters, not a review of video
content or proof of causation. Own-post metrics remain separate, timestamped
observations. Admin analytics imports require the page owner's genuine access
or export. Preserve the original observation time when refreshing public feeds.
The selected creator sample is curated, not an exhaustive search of the market.

Private original media, exact owned-page avatars and branded derivatives enter
through signed chunk/checksum ingestion. Existing D1 stores bounded private
assets; no public media bucket or new paid storage is created. Range playback
requires an authenticated editor. Originals remain unchanged. Branding adds a
footer so the avatar cannot cover source content. A derivative links to its
master, avatar and verified profile; unconfirmed music rights block approval.
The WonPlace avatar currently belongs to the owned X profile; that is not proof
of the LinkedIn showcase-page identity.

The capture step currently recommends evidence and shots. It does not control a
browser. Existing real footage is imported, not represented as a newly executed
capture. New capture workflows must use exact-window browser leases, allowlisted
read-only actions, privacy-safe aggregate screens, and an actual recording
receipt. A missing or failed action cannot become a success claim. The earlier
Spring navigation/invoice failures remain failures.

Release uses the managed coordinator and protected PR review. The release script
imports private media and research only after provider revision reconciliation,
then installs the operator. Live acceptance requires signed-in playback,
publisher identity, dated research, a real completed LLM pass and its persisted
living note, alongside the existing editorial/approval checks. No social posts
are sent by this page or by the scheduled operator.

Stop background decisions with `launchctl bootout gui/$(id -u)
~/Library/LaunchAgents/com.tideline.content-factory-operator.plist`. This preserves
research, lessons, drafts and media. Failed jobs remain visible; stale operator
claims can be reclaimed after their lease expires.
